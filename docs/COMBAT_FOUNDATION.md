# P1-08 発射・弾・命中・熱・勝敗の固定契約

この文書は、規則実行器から受け取った「撃つ」「冷却する」を、同じ固定刻みで処理するための契約である。画面や時計は使わず、`src/simulation/combat.ts`の関数だけで短い戦闘を最後まで再現できるようにする。

## 1. 戦闘状態

初版は1対1に限定する。両機体、弾、競技場、現在刻み、制限刻み、出来事記録を1つの`CombatState`へ持つ。

- 位置、速度、半径、耐久、熱、弾数、待ち時間は安全な整数で持つ。
- 熱は0〜100。発射で増え、冷却で減る。100に到達した発射は成功し、その刻みから90刻み（1.5秒）を過熱停止とする。
- 弾数は発射が成功したときだけ減る。失敗理由が弾切れ、待ち時間、過熱、熱上限、非稼働のときは減らさない。
- 弾は所有者、位置、速度、半径、ダメージ、残り寿命を持つ。寿命は最大2,700刻み、同時存在は1,024個までとする。
- 出来事記録はコードと整数値を使い、1再生4,096件までとする。上限を超えて黙って捨てない。

## 2. 1刻みの処理順

`stepCombat`は、入力配列の順序やJavaScriptオブジェクトの列挙順に頼らず、次の順で処理する。

1. 現在の刻みを1進め、発射待ち時間と過熱時間を1減らす。
2. 操作を機体IDの昇順に並べ、1機体1命令だけ受け付ける。
3. 冷却命令を処理する。熱は0未満にならず、冷却しても過熱残り時間は短くしない。
4. 発射命令を検査する。成功なら弾数を減らし、弾を固定IDで作り、熱と発射待ち時間を加える。失敗なら`ACTION_UNAVAILABLE`だけを記録する。
5. 既存弾と新しい弾を弾IDの昇順で1刻み進める。場外、寿命切れは消す。
6. 各弾は、同じ刻みに重なった対象のうちIDが最も小さい機体へ1回だけ命中する。距離二乗が半径合計の二乗以下なら命中とする。
7. その刻みの全命中を先に集計し、まとめて耐久へ反映する。これにより弾の配列順で同時撃破の結果を変えない。
8. 破壊、時間切れ、引き分けを判定し、終了したら`MATCH_END`を最後に記録する。

弾が同じ刻みに複数命中した場合はすべて有効である。ただし同じ弾が同じ刻みに複数の対象へ当たることはない。所有者自身へは当たらない。

## 3. 勝敗

1. 片方だけの耐久が0以下なら、残った機体の破壊勝利。
2. 両方が同じ刻みに0以下なら引き分け。
3. 制限刻みまで双方が残った場合は、耐久率、熱率の低さ、与えた確定ダメージの順で比べる。
4. すべて同じなら引き分け。ID順で勝者を作らない。

耐久率の比較は`first.health * second.maxHealth`と`second.health * first.maxHealth`の整数積で行い、小数へ変換しない。

## 4. 規則実行器との接続

P1-07の`fire-pulse`は`CombatCommand`の`fire`へ、`cool`は`cool`へ変換する。条件が成立しても装備、弾、待ち時間、熱のどれかで実行できなければ、規則自体を不採用に戻さず`ACTION_UNAVAILABLE`として分析へ渡す。これにより「条件は合っていたが撃てなかった」と「条件が成立しなかった」を分けて表示できる。

## 5. 受入条件

- パルス砲の発射で弾数、熱、待ち時間、弾ID、出来事が同時に固定される。
- 待ち時間、過熱、弾切れ、熱上限、冷却の境界をテストする。
- 距離二乗の境界で命中し、場外・寿命切れ・同じ弾の二重命中が起きない。
- 同時撃破を引き分けとして再現する。
- 時間切れの耐久率、熱、ダメージの順を固定する。
- 20刻み以上の画面なし再生を2回実行し、状態、出来事、勝敗が完全一致する。
- `npm test`、TypeScript検査、`/robobon/`配下のbuild smoke checkを通す。
