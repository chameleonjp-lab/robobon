# P3-15 代表競技場・機体・固定カメラ

- 対象: ロボボン
- 実装日: 2026-08-16
- 状態: コード実装済み。iPhone実機・白黒・初見5人の受入は未実施
- 対応箇所: `src/rendering/battle-renderer.ts`、`src/vertical-slice.ts`

## この節目で固定したこと

戦闘の計算結果と見た目を分離し、戦闘状態のスナップショットだけから代表画面を描画する。描画関数は時刻、乱数、カメラ追従状態を読まないため、同じ状態なら同じ競技場・機体・向きになる。

- Canvasの論理サイズは640 × 360。CSSで縮小しても競技場全体を表示し、カメラを回転・追従・拡大縮小しない。
- 背景は廃材を再利用した試験ドック。固定グリッド、補修線のある2つのドックパネル、中央の`TEST ZONE`を使う。
- 味方は明るい青緑の補修外装と実線の円形床記号、敵は橙色の角張った外装と破線のひし形床記号にする。色を消しても床記号の形と外周が残る。
- 機体は影、脚、本体、補修板、センサー線、砲塔、砲身、耐久バー、識別ラベルの順で描く。砲塔と本体の向きは、現在の相手の座標から決定的に求める。
- 実行中の規則がある間は味方の床記号を紫の太線で囲う。HTMLの規則名・耐久・熱・弾数はCanvasへ焼き込まず、既存の読み上げ可能な表示を使う。
- 弾は機体の上に描き、速度方向の短い弾道を残す。煙、破片、音、画面揺れ、危険区域の動的演出はP3-16以降へ分離した。

## 実装上の契約

`directionToTarget`は、相手と同座標になった場合もID順で右または左へ倒して、ゼロ長ベクトルや`NaN`を作らない。`robotSilhouette`は毎回コピーを返し、デザイン定数を描画中に変更できない。描画へ渡す状態は`CombatState`の検査済み値だけとし、勝敗・命中・弾数・熱などの計算は変更しない。

単体検査では、味方と敵の輪郭が異なること、役割記号が安定すること、水平・垂直・同座標の向きが有限値で一致することを確認する。型検査、全Vitest、Vite build、`/robobon/` build smokeはDraft PRのCIで確認する。
