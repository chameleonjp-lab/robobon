# R01 実装記録：共通戦闘と旧作戦の扱い

更新日：2026-09-08
対象版：`r01-1`
対象ブランチ：`codex/robobon-r01-autonomous-battle`

## 目的

R01では、カードに書いた行動が戦闘で本当に働く状態を作る。画面だけの説明や、射撃だけの別経路は完成条件にしない。画面と自動検査は同じ `stepBattle(state)` を呼ぶ。

## 確定した更新契約

- 1秒を60刻みで進み、6刻み（0.1秒）ごとに、優先順位の上から条件と開始可能性を調べる。
- 条件が合っても開始できない行動は理由を記録して飛ばす。下のカードが開始できれば下のカードを選ぶ。
- 実行中の行動は開始・継続・完了を持つ。未完了の行動は低い優先順位のカードでは中断しない。開始可能な上位カードだけが中断できる。
- 射撃と冷却は行動開始時に1回だけ要求する。射撃は射程、射線、照準、弾、熱、再使用待ちを最後にも確認し、失敗しても弾を消費しない。
- 本体と砲塔の向きは固定小数の256方向で保持する。旋回速度を超えて瞬時に向きを変えない。移動は `stepBody` を通し、後退・横回避・探索・停止で位置と速度を変える。
- 冷却装置の有無、熱、冷却待ちを確認し、冷却量を毎刻み繰り返し適用しない。
- 同じ行動の継続と行動の切り替えを区別し、切り替えは1秒4回を上限にする。
- 条件不成立、開始前の見送り、開始後の最終確認失敗、開始・継続・中断・完了を別記録にする。各記録には規則IDと、該当する場合は行動開始IDを付ける。

## 変更した場所

| 場所 | 内容 |
|---|---|
| `src/simulation/battle-state.ts` | 位置・速度・本体/砲塔方向・実行中行動・作戦・武器・冷却装置・選択記録を一つの状態にまとめた。射線遮蔽、飛来弾、開始可能性もここで判定する。 |
| `src/simulation/battle-step.ts` | 規則選択、行動の保持/中断、移動、最終射撃確認、既存の弾・命中・勝敗計算を一刻みで接続した。 |
| `src/application/game-session.ts` | 画面と検査が共通で使う初期戦闘を作る。プレイヤーと敵の双方が作戦を実行する。 |
| `src/vertical-slice.ts` | 旧ループを `stepBattle` に置き換え、実行中の行動を表示する。結果に開始前の見送りと開始後の失敗を表示する。 |
| `src/storage.ts` | 計算版を `r01-1` に更新。旧 `p1-08` は閲覧用に保持し、明示ボタンで新IDの複製を作る。未知の版は出撃・編集を停止する。 |
| `src/rendering/battle-renderer.ts` | 保存された本体/砲塔方向を描画する。古い位置だけの描画データには従来の固定方向を使う。 |
| `src/simulation/version.ts` | 現行の戦闘計算版を一か所で宣言する。 |

## 完了条件と検査

R01の自動検査では、全7行動（敵へ向く、撃つ、後退、横へ避ける、冷却、探索、停止）の実際の状態変化、条件に合うが開始できない上位カードの見送り、継続、上位中断、再使用待ち、射撃最終失敗、射線、境界、双方実行、同じ初期状態を2回走らせた結果の一致を確認する。

画面導線の検査では、名前なしの出撃停止、名前入力、作戦編集、出撃、一時停止、再開、結果、再戦を確認する。ランキングは検査中に本番へ送信せず、通信失敗時も結果画面が残る既存仕様を使う。

次のコマンドを完了条件にする。

```sh
npm test
npm run build
npm run check:build
```

このブランチでは、`npm ci --ignore-scripts`、`npm test -- --reporter=dot`（22ファイル・99件）、`npm run build`、`npm run check:build`、`git diff --check`をすべて通過させた。

R01では、実機のiPhone Safari、初見利用者、勝敗の面白さ、異なる任務、装備の選択、完全な証拠比較はまだ完了と数えない。これらはR02〜R10で別に確認する。

## 旧作戦の保存規則

旧データを読み込んだだけでは、規則の意味を変更しない。元の識別子・版・条件・否定条件・継続時間を保持して表示し、元データを書き換えない。`元を残して新ルール用に複製`を押した時だけ、新しい識別子と `r01-1` を持つ作戦を作る。保存枠が満杯なら複製を失敗させ、元データを残す。

## R02へ残したこと（R02実装済みの範囲）

R01は「行動が接続された」段階であり、勝てる導入戦を調整した段階ではなかった。R02では射程・地形境界・敵数値・最初の任務を調整し、1枚の変更で被弾や勝敗が変わることを、最小の証拠と再生で確認した。詳細は[`R02_MISSION_BALANCE.md`](R02_MISSION_BALANCE.md)を参照する。
