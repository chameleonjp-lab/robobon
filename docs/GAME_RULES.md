# ロボボン ゲーム規則・数値・データ仕様

- 文書版: 0.2（P1-05作業中）
- 作成日: 2026-08-13
- 状態: P1-05の決定論基盤を反映したレビュー用草案。名称・独自性・数値は未承認
- 対象ゲーム: ロボボン / `robobon`

この文書は、実装者が変わっても同じ戦闘結果になるように、初版の中心規則を固定するための草案である。ここに「暫定」と書いた値は、P1の固定再生検査とP2の5人試遊を通すまで変更できるが、変更時は版を上げ、代表作戦と再生fixtureを更新する。

## 1. プレイヤーが行うこと

プレイヤーは戦闘中のロボットを直接動かさない。次の順で一周する。

1. 任務の問い、敵、競技場を読む。
2. 機体と装備を選ぶ。
3. 「条件なら行動する」という規則カードを上から順に並べる。
4. 15〜45秒の自動戦闘を見る。
5. 戦闘後に、観測事実、該当時間、実行中規則を確認する。
6. 原因を1〜2か所だけ直して再戦する。

勝利だけを成功にしない。損傷量、生存時間、命中機会のいずれかが予想どおり改善し、本人が変更と結果の関係を説明できれば、学習上の成功と記録する。

## 2. 戦闘の時間と状態

| 項目 | 初期仕様 |
|---|---|
| 戦闘時間 | 15〜45秒。任務ごとに上限を定める。初期試作は20秒、初版は45秒 |
| 計算刻み | 1秒を60刻みに分ける。1刻みは勝敗計算へ使う |
| 規則評価 | 100ミリ秒ごと、つまり1秒10回。評価順は常に上から下 |
| 観戦速度 | 1倍と2倍。速度を変えても計算刻み、乱数、結果は変えない |
| 一時停止 | 停止中は勝敗計算を進めない。再開前に確認を出す |
| 背景復帰 | 背景中に計算を追いつかせない。復帰時は確認待ちにして未処理時間を捨てる |
| 終了 | 破壊、時間切れ、または戦闘不能のいずれかで終了する |

### 2.1 終了と勝敗

1. 相手の耐久が0になった時点で破壊勝利とする。
2. 両方の耐久が0になった同じ刻みは引き分けとする。
3. 時間切れでは、残り耐久率が高い側を勝者とする。
4. 残り耐久率が同じ場合は、熱量率が低い側を勝者とする。
5. それも同じ場合は、与えた確定ダメージが多い側を勝者とする。
6. すべて同じ場合は引き分けとする。識別子順で勝敗を作らない。

残り耐久率、熱量率、ダメージは小数を表示しても、比較には固定倍率1,000の整数を使う。計算途中で安全な整数範囲を超えた場合は戦闘を無効にし、勝敗を出さない。

## 3. 位置、向き、距離

- 位置と速度は整数のミリメートル単位で持つ。
- 向きは256分割した角度番号で持つ。実行時に三角関数を呼び出さず、固定した方向表を使う。
- 距離の比較は距離の二乗で行い、平方根の近似値を勝敗へ使わない。
- 同じ刻みで複数の出来事が起きた場合は、`時刻 → 種類の固定順 → 発生元ID → 対象ID` の順に処理する。
- 競技場外へ出る位置、永久に重なる位置、非有限値は不変条件違反として戦闘を停止する。

## 4. 機体と装備

数値はP0の代表作戦を作るための暫定値である。P5で全内容を増やすときも、単純な上位互換を作らない。

| 機体 | 耐久 | 最高速度 | センサー距離 | 役割 |
|---|---:|---:|---:|---|
| スイフト（軽量） | 60 | 140 | 300 | 速いが壊れやすい。距離と回避を学ぶ |
| バランサー（標準） | 90 | 100 | 320 | 規則と装備の試験に使う |
| バスティオン（重装） | 130 | 75 | 340 | 遅いが耐える。距離管理を学ぶ |

### 4.1 P0で使う装備

| 装備 | 弾数 | 射程 | 基礎ダメージ | 再使用待ち | 熱 |
|---|---:|---:|---:|---:|---:|
| パルス砲 | 6 | 250 | 12 | 1.0秒 | 8 |
| 冷却装置 | なし | なし | なし | 2.0秒 | -25 |

パルス砲は、射線が通り、対象が射程内にあり、弾数が1以上で、再使用待ちが0のときだけ発射できる。冷却装置は、熱量が0より大きく、他の行動を中断しても安全なときに使う。装備がない行動を選んだ場合は実行せず、出来事コード`ACTION_UNAVAILABLE`を1回だけ記録する。

## 5. 規則カード

### 5.1 カードの形

1枚は次のデータを持つ。

```text
RuleCard {
  id: 固定識別子
  priority: 上からの順番
  conditions: 条件1〜2個
  action: 行動1個
  parameters: 行動の数値
}
```

P0の入門作戦は条件1個、初版1.0では「かつ」で結んだ条件を最大2個まで許可する。条件の中に別の行動や、前の結果を書き換える処理は入れない。自由なコード入力、ループ、自己書き換えは初版に入れない。

### 5.2 評価と継続

1. 100ミリ秒ごとに、上から順に条件を評価する。
2. 最初に成立したカードの行動を採用する。
3. 成立カードがない場合は、停止または安全な探索行動を行う。
4. 採用中の行動は、完了、中断条件の成立、または上位カードの成立まで続ける。
5. 同じ刻みで複数カードが成立しても、上位1枚だけを採用する。
6. 意図しない行動の切替は1秒4回を超えない。超える場合は中断規則を見直し、隠れた優先処理を追加しない。

### 5.3 条件一覧（P0）

| 条件 | 成立する意味 |
|---|---|
| 敵を確認 | センサー内に敵がいて、遮蔽されていない |
| 敵との距離が近い | 距離が120以下 |
| 敵との距離が射程内 | 距離が250以下 |
| 弾が来ている | 自機へ向かう弾が警戒範囲内にある |
| 弾が残っている | パルス砲の弾数が1以上 |
| 熱が高い | 熱量が70以上 |
| 進行方向が危険 | 次の500ミリ秒で危険区域または壁へ入る |
| 射線が通る | 自機の砲口から対象までに遮蔽物がない |

条件の境界値は「以下」「以上」を含む。例えば距離120は「敵との距離が近い」が成立する。表示上の丸めで境界を変えない。

### 5.4 行動一覧（P0）

| 行動 | 初期仕様 |
|---|---|
| 敵へ向く | 最短回転方向へ向きを変える。回転速度は機体ごとに固定 |
| パルス砲を撃つ | 射線、射程、弾、待ち時間を確認して1発だけ撃つ |
| 後退する | 敵から離れる方向へ移動する |
| 横へ避ける | 直近の弾道と反対側へ、固定時間だけ移動する |
| 冷却する | その場で冷却装置を使い、熱量を下げる |
| 探索する | 低速で固定方向へ進み、敵を探す |
| 停止する | 位置を変えず、砲塔だけを向ける |

## 6. 熱、弾、行動不能

- 熱量の範囲は0〜100。発射で増え、冷却で減る。
- 熱量が100に達した刻みで過熱状態へ入り、1.5秒間は発射できない。
- 過熱中も移動、向き変更、分析用記録は続く。
- 弾数は発射成功時だけ1減る。射線が通らない発射指示では減らさない。
- 行動不能は「規則がない」「装備がない」「条件は成立したが行動できない」を分けて記録する。

## 7. 乱数と再生

P1-05で、同じ戦闘指定を同じ結果へ戻す計算契約を確定した。実装の詳細とfixtureは`docs/SIMULATION_FOUNDATION.md`と`src/simulation/`を正本とする。仕様を変えるときは`simulationVersion`を上げ、対応実行器が残っていない旧版を新版の数値で黙って再計算しない。

- 戦闘指定は、作戦、装備、敵、競技場、内容識別値、計算版、種で構成する。
- `Math.random()`、端末時刻、描画速度を勝敗へ使わない。
- 種は32ビット整数へ正規化し、0は`0x6D2B79F5`へ置き換える。乱数は`(seed, tick, entityId, purpose, index)`の独立ストリームで生成する。
- 状態は項目と順番を固定したリトルエンディアンのバイト列へ変換し、60刻みごとと最終状態のFNV-1a 32ビット指紋を保存する。指紋は再生差分の検出用で、秘密や改ざんの保護には使わない。
- 1描画の計算は最大8刻み。hidden復帰時に未処理時間を追いつかせず、pause/resumeでaccumulatorを破棄する。
- 旧計算版を再実行できない場合は、保存済みの要約と主要出来事だけを表示し、新版で黙って再計算しない。

## 8. 記録する出来事

戦闘中は毎刻みの理由文を保存しない。次のコードと整数値を保存する。

| コード | 例 |
|---|---|
| `TARGET_FOUND` | 対象ID、距離 |
| `RULE_SELECTED` | 規則ID |
| `ACTION_STARTED` | 行動ID |
| `ACTION_UNAVAILABLE` | 行動ID、理由 |
| `PROJECTILE_FIRED` | 武器ID、弾番号 |
| `HIT_CONFIRMED` | 発射元、対象、ダメージ |
| `HEAT_STARTED` | 機体ID、熱量 |
| `HAZARD_ENTERED` | 危険区域ID |
| `MATCH_END` | 終了理由、勝敗 |

1再生は512KB以下、通常は主要出来事と規則別集計だけを残す。開発時の詳細理由はデバッグ出力へ分け、利用者の保存領域へ無制限に追加しない。

## 9. P0-01の合格条件

- 代表4作戦のうち3つ以上を、最大8枚のカードで表現できる。
- V8とJavaScriptCoreで同じ入力の勝敗、主要出来事、固定された識別値が一致する。
- 距離120、250、熱70、弾数0、同時撃破、時間切れを境界fixtureで検査できる。
- 初見5人中4人が、1枚変更後に何が変わるかを予想し、戦闘後に結果を自分の言葉で説明できる。
- 未定義の丸め、同着順、行動中断、乱数用途が残っていない。

この条件を通すまで、P0-02の実装準備を完了扱いにしない。名称と独自性の公開判定は、それぞれ `NAME_REVIEW.md` と `ORIGINALITY_REVIEW.md` の承認欄が埋まるまで未完了とする。
