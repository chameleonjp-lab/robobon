# ロボボン 決定論的シミュレーション基盤

- 版: 0.1
- 対象節目: P1-05
- 状態: 基盤とfixtureを実装済み。移動・衝突・勝敗はP1-06〜08で接続する
- 対象実行環境: V8（Chromium）とJavaScriptCore（Safari）

この文書は、描画の速さや端末時刻を戦闘結果へ混ぜず、同じ戦闘指定を同じ計算へ戻すための最低限の契約を定める。ハッシュは再生差分を見つける指紋であり、改ざん検知や秘密の保護には使わない。

## 1. 固定値と安全範囲

| 項目 | 契約 |
|---|---|
| 権威値 | `Number`の安全整数で持つ。値の絶対値は`2,000,000,000`以下 |
| 表示用の小数 | 固定倍率`1,000`の整数へ変換してから計算する |
| 丸め | `.5`はゼロから遠ざける（half away from zero） |
| 加算・積算 | 範囲検査後に実行し、超過時は`RangeError`で戦闘を無効にする |
| 固定値の積算 | `BigInt`で中間積を保持し、倍率で割ってから範囲検査する |
| 角度 | 実行時の三角関数ではなく、P1-06で固定した256方向表を参照する |

`Number.MAX_SAFE_INTEGER`ぎりぎりの値や、`NaN`、`Infinity`、暗黙の文字列変換はゲーム状態へ入れない。境界を越えた戦闘は勝敗を出さず、保存済みの正常な作戦を消さない。

## 2. 固定刻みクロック

- 1秒を60刻み、標準刻みは`1000 / 60`ミリ秒とする。
- `FixedStepClock`は1回の描画で最大8刻みだけを実行する。
- 8刻みを超える遅延分はゲーム時間へ加算せず、accumulatorを0へ捨てる。追いつきの無限ループを作らない。
- `document.visibilityState === "hidden"` では呼び出し元が`pause()`を実行する。`pause()`は未処理時間を捨てる。
- `resume()`後は新しい経過時間から始め、確認が終わるまで戦闘を再開しない。
- 2倍速は描画要求を増やさず、同じ上限内でシミュレーション時間の倍率だけを指定する。

P1-05のfixtureでは刻み幅を10ミリ秒へ置き換え、25ミリ秒、追いつき超過、停止・復帰を検査する。実時間が16、100、1,000、30,000ミリ秒飛んでも、1描画の刻み数は8以下であることを後続のブラウザ検査へ引き継ぐ。

## 3. 独立乱数ストリーム

乱数は`Math.random()`や端末時刻を使わず、次の5要素を毎回明示して生成する。

```text
(seed, tick, entityId, purpose, index)
```

`purpose`は`spawn`、`aim`、`damage`、`effect`の固定タグへ変換する。アルゴリズムは32ビット符号なし整数、`Math.imul`、MurmurHash3 finalizer相当の`mix32`を順に適用し、同じ組へ同じ値を返す。seedの32ビット化後、0だけは`0x6D2B79F5`へ置き換える。

目的や発生順が変わっても別のストリームを読むため、弾の追加が後続のダメージ乱数列をずらさない。`randomUint`は32ビット値、`randomUnit`は`[0, 1)`の値を返す。タグの追加・変更は計算版を上げ、既存fixtureを更新する。

## 4. 状態バイト列とハッシュ

状態ハッシュは、順番を固定したリトルエンディアンのバイト列へ変換してからFNV-1a 32ビットで計算する。

```text
magic(0x52424E31) | hashVersion | tick | entityCount |
entity.id | x | y | vx | vy | health | heat | active(0/1) ...
```

エンティティはIDの昇順で並べ、座標・速度・耐久・熱は全て符号付き32ビット整数として検査する。毎60刻みと最終状態の`0x........`指紋を保存し、V8とJavaScriptCoreで勝敗・主要イベント・指紋を照合する。ハッシュ不一致は既存保存を上書きせず、再生非対応または破損として隔離する。

## 5. 自動fixtureと未完了範囲

`src/simulation/*.test.ts`で次をCIへ組み込んだ。`golden.test.ts`には乱数値`3,814,058,794`と状態指紋`0xf4fbdbda`を固定し、実装の意図しない変更を検出する。

- 固定小数の丸め、加算・積算の上限、非有限値の拒否
- 同一乱数tupleの再現、目的・indexごとの独立性、seed 0の正規化
- 1描画8刻み上限、遅延バックログの破棄、hidden相当の停止・復帰
- エンティティ順に依存しない状態バイト列、値変更によるハッシュ変化、破損値の拒否

この節目ではまだ機体移動、衝突、規則実行、発射、保存、旧計算版の再生器を実装しない。P1-06〜08で状態項目を増やすときは、この文書のバージョンとgolden fixtureを同じ変更で更新する。

## 6. 受入条件

- `npm test`の5テストファイルが全て成功し、型検査と`/robobon/` build smoke checkも成功する。
- V8とJavaScriptCoreで同一fixtureの勝敗、主要イベント、60刻みごとの指紋、最終指紋が一致する。
- 1描画の刻み数が8を超えず、hidden中にtickが進まず、復帰時に未処理時間を追いつかせない。
- 安全整数、境界丸め、同着順、乱数用途、状態バイト列の順番に未定義が残らない。
- 仕様変更時は`simulationVersion`を上げ、対応実行器がない旧版を新版の数値で黙って再計算しない。
