# ロボボン ビジュアル設計書

- 版: 0.1
- 対象: P0-04の方向確認
- 状態: 4画面の低精細見本を作成済み。完成素材とロゴは未確定
- 対応基準幅: 320 CSSピクセル以上
- 基準画面: 320 × 568 CSSピクセル、縦向き

この文書は、絵を増やすためではなく、画面が同じ作品に見え、必要な情報が隠れないようにするための基準である。見本画像は方向確認用で、完成素材として扱わない。

## 1. 作品の見た目を決める3本柱

1. 戦場ではなく、廃材を再利用した試験場として見せる。
2. 軍用兵器ではなく、補修しながら使う小型作業機として見せる。
3. 編集、戦闘、分析で同じ判断記号を使い、整備班が読む試験記録として画面をつなぐ。

「暗い金属と発光」だけでは作品の顔にならない。明るい外装板、補修板、検査番号の配置、試験記録の余白を組み合わせ、機体と判断の関係を見せる。

## 2. 使う表現と使わない表現

### 使う

- 明るい陶器状または塗装済みの外装板
- 暗い内部機構、補修板、細いセンサー表示
- 斜め上から見た固定視点
- 状態を示す細い発光線と、床に置く形状記号
- 試験番号、時間線、規則カードの縦の並び

### 使わない

- 実在軍の記章、国旗、企業ロゴ
- 元作品に近い機体輪郭、画面配置、用語、音
- 文字や機体を覆う動く走査線、強い色ずれ、過度なノイズ
- 写真のような汚れを全画面へ敷く表現
- 爆発、煙、点滅で重要対象を隠す表現

独自性の確認は、名前を隠した状態でも行う。見本4枚で同じ作品に見える統一性と、既存作品に似過ぎない差分を別々に記録する。

## 3. 画面の寸法、安全領域、余白

| 項目 | 初期基準 | 実装上の扱い |
|---|---:|---|
| 最小幅 | 320 CSSピクセル | 横スクロールを発生させない |
| 基準高さ | 568 CSSピクセル | 下部の操作が隠れないか確認する |
| 内容左右余白 | 12px（幅320）、16px（幅375以上） | 8px単位を基本にし、狭い画面だけ4pxを許可 |
| タップ対象 | 44 × 44 CSSピクセル以上 | 主要操作は別の操作と重ねない |
| 画面上端・下端 | `env(safe-area-inset-*)`を加える | 固定バーを安全領域の外へ置かない |
| 文字拡大 | 200%でも操作順を維持 | 横方向のページスクロールと重なりを0にする |

画面幅に応じてカードの列数を変える。固定した横幅のパネルを押し込まず、画面全体、上部情報、主操作、補助情報の順に縮める。iPhoneとiPadで比率が変わっても、メニューや重要な説明を隠さない。

## 4. 色と形の役割

色だけで状態を伝えない。各色へ、形、線、記号、文章のいずれかを必ず組み合わせる。

| 役割 | 初期色 | 色以外の手掛かり |
|---|---|---|
| 背景 | `#0B1118` | 装飾を抑えた無地面 |
| 面・カード | `#131E29` | 境界線と8px間隔 |
| 主文字 | `#F2F6F8` | 太さと大きさ |
| 補助文字 | `#AAB7C4` | 主文字より一段小さい階層 |
| 味方 | `#46D9E8` | 実線の円形床記号 |
| 敵 | `#FF9A5C` | 破線のひし形床記号 |
| 実行中規則 | `#C4A7FF` | 左側の太線と再生記号 |
| 注意 | `#FFB84D` | 三角形と短い説明 |
| 即時危険 | `#FF5D6C` | 山形、太い境界、危険記号 |
| 成功 | `#77D68A` | チェック記号と結果文 |

通常文字は背景に対して4.5対1以上、重要な図形・境界・選択状態は3対1以上を目標にする。最終値は実装した背景との組み合わせで測り、見本の色をそのまま合格値とはしない。

## 5. 文字とアイコン

- 本文16/24、補助14/20、節見出し20/28、画面見出し28/34 CSSピクセルを初期値にする。
- 耐久、熱、時間は等幅の数字を使う。
- 操作や状態を説明する文字を画像へ焼き込まず、HTMLで表示する。
- アイコンは24 × 24のSVGを基準にし、同じ線幅、角、余白を使う。
- 規則カードは条件を輪郭、行動を塗りで分けるが、日本語ラベルを併記する。
- フォーカス状態、押下状態、無効状態を同じ部品で定義する。

絵文字を製品アイコンの代わりに使わない。SVGは単純な図形と画面記号に限定し、文字情報はDOMへ置く。

## 6. 6画面の情報設計

| 画面 | 最初に見せるもの | 次の操作 | 隠してよいもの |
|---|---|---|---|
| ホーム | 作品の一文と主操作 | 任務を見る / 続きから組む | 補足説明、更新情報 |
| 任務 | 敵、競技場、問い | 任務を選ぶ | 長い世界設定 |
| 格納庫 | 機体の輪郭と役割 | 機体・装備を選ぶ | 数値の細部 |
| 作戦編集 | 上から読む規則列 | 追加、変更、上下移動 | 高度な説明 |
| 戦闘 | 飛来弾、危険区域、向き | 一時停止、記録して戻る | 装飾粒子、細かな床跡 |
| 分析 | 観測事実と該当場面 | 再生、実験案を選ぶ | 証拠のない原因候補 |

P0-04ではホーム、作戦編集、戦闘、分析の4枚を見本にした。任務と格納庫は同じカード、見出し、機体輪郭を使って後から追加する。

## 7. 描画順と情報の優先順

### Canvasの描画順

1. 背景と競技場の線
2. 危険区域の境界
3. 床の影と床記号
4. 機体の本体、脚、砲塔
5. 弾道と弾
6. 命中、煙、破片、床跡
7. HUDの背景
8. 実行中規則、耐久、熱、警告

重要なHTML表示はCanvasの外へ置き、読み上げと拡大を可能にする。煙や爆発で機体、弾道、危険境界を150ミリ秒を超えて隠さない。

## 7.1 P3-15代表画面の実装

P3-15では、計算状態から競技場全体を描く固定カメラを`src/rendering/battle-renderer.ts`へ分離した。廃材を再利用した試験ドック、味方の実線円、敵の破線ひし形、補修外装、脚、砲塔、センサー線、影、耐久バーを代表画面へ入れ、現在の相手座標から本体と砲塔の向きを決定する。描画関数は時刻と乱数を使わず、戦闘結果の計算へ触れない。

この節目では、武器の命中演出、煙、破片、音、揺れは追加しない。これらは弾道と重要状態の視認性を確認した後、P3-16で段階的に追加する。コード検査は済んでいるが、白黒・320 × 568・初見5人・iPhone性能の受入は未実施として記録する（詳細: `docs/P3-15_RENDERING.md`）。

### 画面で守る順番

飛来弾と危険区域 → 機体の向き → 実行中規則 → 耐久と熱 → 命中確認 → 飾り、の順で守る。演出上限に達したら、床跡、薬きょう、細かな火花、煙の順に減らす。

## 8. 動きと音

- カメラを回転させず、競技場全体を見せる。
- 大きな被弾の揺れは最大3px、120msまでとする。HUDは揺らさない。
- 命中時の動きの弱まりは0.05〜0.10秒に限定する。
- 動きを減らす設定では、揺れ、色ずれ、強い拡大縮小、不要な粒子を止める。
- 音なしでも警告、命中、停止理由を画面で説明する。
- 音は利用者の最初の操作後に開始し、効果音と音楽を別に切り替える。

OSの動きを減らす設定も受け取り、ゲーム内の「演出を減らす」と別々に確認する。画面の動きが減っても、規則の結果や重要な弾道を削らない。

## 9. 4枚の見本と素材管理

| 見本 | 素材ID | 目的 |
|---|---|---|
| ホーム | `sample.home.v1` | 主操作、中央の機体、3枚の操作カード |
| 作戦編集 | `sample.planner.v1` | 縦の規則列、選択中の強調、上下方向 |
| 戦闘 | `sample.battle.v1` | 弾道、危険区域、機体の向き、下部HUD |
| 分析 | `sample.analysis.v1` | 時間線、事実カード、次の実験候補 |

4枚は`public/assets/visual-samples/`に置き、`public/assets/asset-manifest.json`と`docs/ASSET_CATALOG.md`で同じIDを参照する。出典が空の素材、仮素材のまま完成扱いにした素材、重複IDを配信物へ入れない。

## 10. 受入条件

- 4枚を名前なしで見ても、初見5人中4人以上が同じ作品の画面だとまとめられる。
- 白黒化しても、味方・敵・実行中規則・危険区域・主操作の意味が形で残る。
- 320 × 568 CSSピクセル、幅375以上、200%文字で横スクロール、切れ、主要操作の隠れがない。
- 主要操作のタップ対象が44 × 44 CSSピクセル以上で、ドラッグだけに依存しない代替操作を持つ。
- 4枚の見本と配信物の素材IDが一致し、仮素材・未登録素材・権利欄の空白が0件である。
- 既存作品との比較で強い一致が指摘された場合、公開へ進まず、輪郭、用語、構図、色、音の差分を再設計する。
