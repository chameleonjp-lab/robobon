# ロボボン 移動・センサー・衝突の基盤

- 版: 0.1
- 対象節目: P1-06
- 状態: 固定刻みへ接続する計算とfixtureを実装済み。規則実行・弾・演出は後続節目で接続する
- 正本: `src/simulation/motion.ts`、`geometry.ts`、`sensor.ts`

この文書は、機体が同じ入力から同じ位置・向き・センサー結果になるための契約を定める。描画の座標変換や画面の大きさは、計算結果へ影響させない。

## 1. 単位と向き

- 位置、速度、半径は整数ミリメートルで持つ。
- 向きは256段階の番号で持つ。番号0は右、64は下、128は左、192は上を指す。
- 方向ベクトルは倍率1,000の固定配列としてソースへ保存する。実行時に三角関数を呼び出さない。
- 速度を方向へ変換するときは、固定配列との積を大きな整数を正確に扱う型（`BigInt`）で計算し、0.5をゼロから遠ざけて整数化する。
- 最短回転の差が±128で同じ場合は、-128側を選ぶ。順番や端末で回転方向が変わらない。

## 2. 1刻みの移動

1刻みは次の順で処理する。

1. その刻みの速度を決める。
2. `次の位置 = 現在の位置 + 速度` を安全整数として計算する。
3. 機体の半径を含む競技場内側へ位置を収める。
4. 壁へ押し出された軸の速度を0にする。

境界は`min + radius`から`max - radius`までを機体中心の範囲とする。競技場が機体を収容できない場合は計算を止め、勝敗を出さない。背景復帰の経過時間をまとめて移動へ反映しない。

## 3. センサー

- 距離は平方根を取らず、座標差の二乗を`BigInt`で比較する。
- センサー範囲以下、双方が有効、遮蔽指定がない場合だけ「見えている」とする。
- 対象方向は256方向表との内積が最大の番号を選ぶ。同点は方向とのずれが小さい番号を選び、それも同じなら小さい番号を選ぶ。
- 同じ位置の対象は、観測者の現在の向きを対象方向として扱う。
- センサー結果には対象ID、距離の二乗、範囲内、可視、対象方向、相対角を保存する。表示用の距離へ丸めてから判定しない。
- 指定した刻み数後に壁の外へ出る場合は、x/y軸ごとの境界危険と全体の危険を返す。

この節目では壁による射線遮蔽の形状計算を追加しない。`readSensor`へ遮蔽結果を明示的に渡す入口だけを用意し、P1-08の弾道・遮蔽物で同じ判定順を使う。

## 4. 機体同士の衝突

- 無効な機体は衝突判定から除外する。
- 判定は円の半径合計と距離の二乗を比較する。平方根や端末依存の物理エンジンは使わない。
- 接触した組はIDの昇順で処理する。入力配列の順番で有利不利が変わらない。
- 重なりをx/yのうち浅い軸へ分けて解消し、奇数ミリメートルの余りは小さいIDへ割り当てる。
- 同じ位置の組はx軸を使う。近づいていた軸の速度は0にする。
- ちょうど接するだけの組は衝突イベントとして返すが、余分な移動はしない。

これはP1-06の機体同士の最小解決である。弾、壁、危険区域の形状とダメージはP1-08で別の契約にし、同じID順と安全整数検査を再利用する。

## 5. 自動fixture

`src/simulation/motion.test.ts`、`geometry.test.ts`、`sensor.test.ts`で次を固定した。

- 256方向表の四方位、固定速度、最短回転と±128の同着
- 半径を含む境界クランプと、外向き速度の停止
- 距離二乗、ID順に依存しない重なり解消、奇数ミリメートルの配分
- センサー範囲、遮蔽指定、無効対象、同位置の向き
- 将来の境界超過と、現在位置だけでは危険でないケース

## 6. 受入条件

- V8で全fixtureが成功し、既存の固定刻み・状態ハッシュ・build smoke checkも成功する。
- 方向表、回転の同着、境界、衝突のID順、センサーの距離比較に未定義の丸めがない。
- 画面幅、描画速度、入力配列の順番を変えても、同じ機体入力の位置・向き・センサー結果が一致する。
- 競技場外、収容不能な半径、非有限値、安全整数超過は勝敗を出さずに停止する。
- P1-07へ渡す作戦状態は、機体ID順・規則評価順を明示し、移動計算と描画を混ぜない。
