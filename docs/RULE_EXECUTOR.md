# P1-07 規則実行器の固定契約

この文書は、縦に並べた規則カードを同じ入力から同じ順で評価し、採用・継続・完了・中断・不採用を再生できるようにするための実装契約である。画面やCanvasはこの層へ依存させず、`src/simulation/rules.ts`を画面なしのテストから利用する。

## 1. 入力と上限

- 規則は0〜12枚。配列の位置が優先順位で、0が最上位である。`priority`は必ず配列位置と一致させる。
- 規則IDはASCII小文字、数字、`.`, `_`, `-`の1〜32文字で、重複させない。
- 条件は1枚につき0〜2個。同じ条件を1枚へ重ねず、条件は論理積（かつ）で評価する。空の条件は明示的なフォールバックとして常に成立する。
- 行動は自由なコードではなく、固定された`ActionId`から1つだけ選ぶ。`eval`、ループ、自己書き換えは使わない。
- 数値は安全な整数として検証する。`durationTicks`は1〜600（1〜10秒）に制限し、範囲外は保存・再生を停止する入力エラーとする。

条件IDは`enemy-visible`、`enemy-near`、`enemy-in-range`、`projectile-warning`、`ammo-available`、`heat-high`、`boundary-danger`、`line-of-sight`の8個、行動IDは`face-target`、`fire-pulse`、`retreat`、`strafe`、`cool`、`explore`、`stop`の7個から始める。

## 2. 1回の評価

1. 同じ刻みのセンサー値を`RuleFacts`として固定する。
2. 配列の0番目から順に、各条件の実値と期待値を比較する。期待値を省略した条件は`true`、`false`を指定した条件は否定条件となる。
3. すべての条件が成立した最初のカードだけを`matched-first`として返す。
4. どのカードも成立しない場合は`no-match`を返し、行動を勝手に発明しない。
5. 各カードの条件結果（実値、期待値、成立/不成立）を監査用に返す。これが不採用理由の根拠になる。

同じ入力、同じ配列順なら、オブジェクトの列挙順や画面更新のタイミングに左右されず同じ`RuleSelection`になる。

## 3. 継続、完了、中断

行動の標準継続刻みは次のとおり。カードに`durationTicks`がある場合だけ、そのカードの値で上書きする。

| 行動 | 標準継続 | 意味 |
|---|---:|---|
| `face-target` | 1刻み | 対象へ向きを合わせる |
| `fire-pulse` | 1刻み | 1回の発射を試みる |
| `retreat` | 6刻み | 危険から離れる |
| `strafe` | 6刻み | 横方向へ回避する |
| `cool` | 12刻み | 熱を下げる |
| `explore` | 12刻み | 安全な探索を続ける |
| `stop` | 1刻み | 停止する |

`advanceAction`の判定は次の固定順で行う。

- 実行中の行動がなければ、採用カードを`started`、カードがなければ`idle`とする。
- 継続刻みの途中で同じカードが成立したら`continued`とする。
- 継続刻みに到達したら`completed`を1回返し、次の刻みで改めてカードを選ぶ。
- 実行中より上位（小さい`priority`）のカードが成立した場合だけ、途中でも`interrupted`として新しい行動へ移る。
- 下位または同順位の別カードは、実行中の行動が完了するまで`lower-priority-held`として採用しない。
- カードが1枚も成立しないときも、実行中で未完了なら`no-match-while-active`として継続する。完了後は`idle`へ戻る。

状態遷移は`null → started → continued* → completed → null`、または`continued* → interrupted → started`に限定する。`lastTick`以下の刻みを渡すこと、完了済み状態を二重完了させることは不変条件違反として停止する。

## 4. 切替の上限

`ActionSwitchGuard`は60刻み（1秒）の窓で異なる`ruleId:action`への切替を数える。同じ行動の再評価は切替に数えない。1窓で4回を超える切替は拒否し、現在の行動を保持する。次の窓でカウントを0へ戻す。

この制限は判断を隠すためではない。閾値付近の規則が毎秒何度も揺れる場合に、カードの優先順位・継続時間・条件境界を見直すための検出器である。拒否は`switch-rate-limit`として記録し、無言で別の行動へ置き換えない。

## 5. 監査とテスト

1回の評価結果は、毎刻みの文章ではなく、規則ID、条件コード、実値/期待値、`started`、`continued`、`completed`、`interrupted`、`idle`、`switch-rate-limit`の数値イベントへ変換する。詳細な理由文は開発用に限定し、保存データを無制限に増やさない。

P1-07の受入は次を満たすこと。

- `src/simulation/rules.test.ts`で、先頭一致、否定条件、不採用、順序検証、継続、完了、上位中断、下位保留を固定fixtureで確認する。
- 同じカードを再評価しても切替数が増えず、60刻み内の5回目の異なる行動を拒否する。
- `npm test`、型検査、`/robobon/`配下のbuild smoke checkが通る。
- 画面、音、保存、ネットワークへ依存せず、後続のP1-08（発射・熱・勝敗）から同じ関数を呼び出せる。
