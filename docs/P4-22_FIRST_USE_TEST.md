# P4-22 初見確認と修正

## 目的

P4-21で追加した3任務と段階説明が、説明を受けていない人にも伝わるかを確認する。これは利用者テストの記録を整える作業であり、まだ5人の確認を実施したという意味ではない。

## 記録方法

外部送信は行わず、確認者ごとに次だけを匿名で記録する。

| 項目 | 内容 |
|---|---|
| 匿名ID | `u01`のような連番。氏名・連絡先は保存しない |
| 端末 | iPhone機種、iOS、Safariの版 |
| 任務 | 1〜3のどれを最初に選んだか |
| 意味のある入力まで | 秒数。30秒以内か |
| 導入戦終了まで | 秒数。60秒以内か |
| 問いの説明 | 本人の言葉で説明できたか |
| 次の操作の説明 | 次に何を変えるか説明できたか |
| 自発的な再戦 | 説明なしにもう一度試したか |
| 観察メモ | 迷った場所、発言、途中離脱。個人を特定する内容は書かない |

同じ人の再確認は新しい参加者として数えない。途中離脱や欠測は成功として数えず、理由を匿名メモへ残す。確認者が5人に満たない場合、割合による合格を宣言しない。

## 合否の集計

`src/first-use.ts`の`evaluateFirstUse`へ、5人分の記録を渡す。次の4項目をそれぞれ5人中4人以上で満たすことを早期目標とする。

- 意味のある入力を30秒以内に行う
- 導入戦を60秒以内に終える
- 任務の問いを自分の言葉で説明する
- 次の操作を自分の言葉で説明する

4項目をすべて満たしたときだけ`pass`とする。5人未満は`insufficient-data`、未達かつ改善2回未満は`improve`、改善2回後も未達なら`stop-or-redesign`とする。未達を平均値で隠さず、各項目の人数を記録する。

## 確認手順

1. 画面を初期状態へ戻し、任務や規則の説明を事前にしない。
2. 最初に意味のある入力をした時刻を記録する。
3. 導入戦が終わるまで、操作を誘導せず観察する。
4. 任務の問い、見えている段階、次にする操作を本人の言葉で尋ねる。
5. 発言、迷い、離脱、再戦の有無を匿名記録へ残す。

P4-20の「事実／不足／実験案」の理解確認も同じ確認者へ混ぜず、P4-20の未実施記録として別集計する。確認できるまで、P4-22を完了扱いにせず、P5の内容追加へ進まない。

## 修正と停止

未達があった場合は、問いの文章、段階説明の順番、カードの情報量のうち一つだけを変更し、最大2回まで再確認する。2回後も5人中3人未満が任務の問いと次の操作を説明できない場合は、任務選択を減らすか段階説明を再設計する。新しい任務、装備、報酬で迷いを隠さない。

名称・独自性、保存、実機性能、Pages公開の判定はこの確認だけでは通過しない。別の公開ゲートで記録する。
